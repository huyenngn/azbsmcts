\section{Introduction}

Board games are popular domains for artificial intelligence (AI) research because they provide controlled environments with clear rules and objectives.
In recent years, learning-based approaches have achieved great success in games with perfect information, where all players can observe the full game state at any given time.
One example is AlphaZero, which combines deep neural networks with Monte Carlo Tree Search (MCTS) and performs at a superhuman level in games like chess, shogi and go.\cite{Silver2017alphazero}

Games with imperfect information, however, present a different set of challenges.
Players do not have access to the full game state and must make decisions based on partial observations.
This requires agents to reason over multiple possible hidden states of the game, which can lead to fundamentally different strategic considerations compared to perfect information games and remains a challenge for AI systems to handle effectively.

\subsection{Motivation}

A particularly challenging domain for search-based methods due to its large state space and the significant uncertainty introduced by hidden information is Phantom Go, a variant of Go where players cannot see the opponent's stones on the board. Instead, they receive limited feedback about moves and captures, requiring them to reason about multiple possible board states consistent with their observations.

A common approach to handling imperfect information is determinization, where hidden information is filled in by sampling a fully observable game state and then applying standard algorithms such as MCTS.
While simple, this approach is known to suffer from fundamental problems such as strategy fusion and non-locality, which can lead to systematically poor decisions.
More advanced methods, such as Belief-State Monte Carlo Tree Search (BS-MCTS), address this issue by explicitly maintaining and reasoning over a set of possible hidden states rather than committing to a single guessed reality.\cite{Wang2015bsmcts}

At the same time, AlphaZero-style methods rely on assumptions that do not hold in Phantom Go.
AlphaZero evaluates positions and selects actions based on a neural network that takes the full game state as input. In an imperfect information setting, such a state does not exist from the agent's perspective. Simply applying AlphaZero to Phantom Go therefore leads to conceptual and practical failures:
the neural network is trained on information the agent does not actually have and the resulting policy and value estimates become unreliable.

\subsection{Research Question}

This thesis aims to explore how AlphaZero can be adapted for imperfect information games such as Phantom Go and how it compares empirically to standard belief-state search methods.

The focus is on integrating belief-state reasoning into the AlphaZero framework.
Instead of assuming full observability, the proposed approach combines BS-MCTS with a neural network trained through self-play, following the general structure of AlphaZero while explicitly accounting for hidden information.

The main contributions of this thesis are:

\begin{itemize}
  \item An implementation of BS-MCTS for Phantom Go using the OpenSpiel framework.
  \item The design of an AlphaZero-inspired agent that operates on belief-state information rather than fully observed game states.
  \item An empirical evaluation comparing BS-MCTS and the proposed AlphaZero-inspired approach under controlled experimental conditions.
\end{itemize}

The goal of this work is not to achieve state-of-the-art performance, but to clarify how learning-based search methods behave in imperfect information settings and to identify the practical challenges that arise when extending AlphaZero-style systems beyond perfect information games.

\section{Background and Related Work}

\subsection{Phantom Go and Imperfect Information}

Imperfect information games are games in which players do not have full access to the current state of the environment. Decisions must therefore be made under uncertainty, based on partial observations.

Phantom Go is an imperfect information variant of Go.
While the underlying game mechanics are identical to standard Go, players cannot observe the opponent's stones on the board. Instead, each player only sees their own stones, revealed opponent stones and limited feedback about opponent moves, such as whether an opponent move was valid, was a pass, caused captures or
resulted in an observation.

Because the true board state is hidden, a player must reason about multiple possible game states that are consistent with the observations received so far. Two different hidden states may appear identical to the player while differing in strategically important ways. This makes Phantom Go significantly more challenging than standard Go and unsuitable for algorithms that assume full observability.\cite{Cazenave2006phantomGo}

\subsection{Monte Carlo Tree Search}

Monte Carlo Tree Search (MCTS) is a search algorithm widely used in game-playing agents.
It incrementally builds a search tree by repeatedly simulating games from the current position.
Each simulation consists of four phases: selection, expansion, simulation and backpropagation.

In games with perfect information, MCTS has been highly successful, particularly when combined with domain-specific heuristics or learned evaluation functions.\cite{Browne2012mcts}
However, standard MCTS assumes that the full game state is known, which does not hold in Phantom Go.


\subsection{Determinization and IS-MCTS}
\label{sec:determinization}

A common approach to applying MCTS in imperfect information games is \emph{determinization}: sampling a fully specified game state that is consistent with a player's observations and then applying standard MCTS as if this sampled state were the true state. Information Set Monte Carlo Tree Search (IS-MCTS) improves on naive determinization by organizing the search around information sets and can reduce some effects of inconsistencies that arise from hidden information.

Nevertheless, determinization-based approaches and IS-MCTS variants can suffer from fundamental failure modes in Phantom-style games. Two well-known issues are \emph{strategy fusion} and \emph{non-locality}.\cite{Cowling2012ismcts} Strategy fusion refers to situations where planning implicitly assumes it can select different actions depending on hidden information, even though such distinctions are not observable to the player. Non-locality refers to cases where the value or legality of an action depends strongly on hidden details that are not represented at the player's information level, which can make search statistics misleading across different hidden states.

These issues limit the effectiveness of determinization-based methods in complex imperfect information games.


\subsection{Belief-State MCTS}

Belief-State Monte Carlo Tree Search (BS-MCTS) was proposed to address the limitations of determinization. Instead of committing to a single guessed hidden state, BS-MCTS maintains and reasons over a set of possible states that are consistent with the agent's observations.

During search, actions are evaluated across multiple sampled states and their outcomes are aggregated to guide decision-making. This allows the agent to account for uncertainty explicitly rather than treating it as noise.

Wang et al. describe additional mechanisms such as opponent guessing and opponent predicting to improve belief handling during search and demonstrate effectiveness in Phantom games including Phantom Go.\cite{Wang2015bsmcts}

BS-MCTS serves as an important baseline in this thesis and provides the foundation for integrating belief-state reasoning with learning-based methods.

\subsection{Particle-Based Belief Approximation}

In partially observable environments, an agent does not know the true state of the system and instead maintains a belief state representing a probability distribution over all states consistent with its observations. Exact belief representations quickly become intractable as the number of possible states grows, which is common in complex domains such as board games with hidden information.

A common practical solution is to approximate the belief distribution using a finite set of samples known as particles. Each particle represents one possible hidden state that is consistent with the agent's observations. Together, the particle set approximates the underlying belief distribution. This idea originates from Sequential Monte Carlo methods, also known as particle filters, which represent probability distributions through weighted samples that are periodically resampled to avoid degeneracy and maintain diversity in the particle population \cite{Doucet2007particle}\cite{Arulampalam2002tutorial}.

Particle-based belief representations are widely used in partially observable planning and have been successfully combined with Monte Carlo Tree Search. For example, Partially Observable Monte Carlo Planning (POMCP) samples states from a particle belief representation to perform search without explicitly enumerating the entire belief distribution \cite{Veness2010pomdps}. These approaches demonstrate that particle-based approximations provide a practical way to reason about uncertainty in large state spaces.



\subsection{AlphaZero and Learning-Based Search}

AlphaZero is a learning-based game-playing system that combines MCTS with deep neural networks trained through self-play.
A policy network provides prior probabilities over actions, while a value network estimates the expected game outcome.
These networks guide MCTS and the improved policies produced by search are used as training targets for further learning.\cite{Silver2017alphazero}

AlphaZero has achieved success in games with perfect information, but it relies on the assumption that the full game state is observable.
In imperfect information games, this assumption no longer holds. The neural network cannot be given the true state as input and naively training on hidden information leads to inconsistent or invalid evaluations.

Several works explore combining deep reinforcement learning and search in imperfect information settings, including ReBeL, which integrates search with learned components for imperfect-information games.
However, applying this approach to games like Phantom Go remains challenging due to the large state space and the difficulty of representing uncertainty effectively.\cite{Brown2020rebel}

\subsection{Positioning of This Work}

This thesis builds on prior work in belief-state search and learning-based game play.
It uses BS-MCTS as a baseline for handling uncertainty in Phantom Go and investigates how the core ideas of AlphaZero can be adapted to operate on belief-state information rather than fully observed states.

The focus is not on proposing a new theoretical framework, but on studying the practical interaction between belief-state reasoning, Monte Carlo Tree Search and self-play learning in an imperfect information setting.


\section{Problem Formulation}

\subsection{Game Setting}

Phantom Go is a two-player, turn-based, zero-sum game derived from the game of Go.
As in standard Go, players alternate placing stones on a board and the game ends when both players pass consecutively.
The final score is determined by territory and captured stones.

The key difference from standard Go is that players do not observe the opponent's stones on the board. At any point, the true board state is hidden.
Instead, players receive partial feedback related to validity of moves, observational nature of moves and captures.
These observations restrict the set of possible board states but never fully determine it.

In OpenSpiel's implementation of Phantom Go, the game proceeds deterministically given the full hidden state, but the information available to each player is incomplete.

\subsubsection{Modifications to the OpenSpiel Implementation}
\label{sec:openspiel_mods}

In OpenSpiel's implementation of Phantom Go, the game can theoretically go on indefinitely if both players continue to make moves without passing.
Players can also stall by repeating the same observational moves that do not change the board state and, therefore, do not progress the game in any meaningful way. This had led to excessive game lengths and drain of computational resources during preliminary testing.

To prevent this, a maximum game length is enforced, after which the game is terminated and scored according to the current board state.
The cutoff point must balance the constraints of computation time while still providing a buffer big enough for observational exploration and any prolonged strategic maneuvering.

A game length discount is applied to the value of terminal states, encouraging agents to win more quickly.
This avoids sudden cutoff and leads the game to a more natural conclusion.

Lastly, a mechanism is in place to detect repeated observational moves, preventing players from stalling indefinitely.



\subsection{Observations and Agent Perspective}

At each turn, the agent observes a partial view of the board together with limited feedback about the last move, such as:

\begin{itemize}
  \item Whether the last attempted move was valid, invalid or observational.
  \item Whether stones were captured as a result of the last move and how many.
  \item Whether the last move was a pass.
\end{itemize}

This observation summarizes the information available to the player but does not reveal the full game history or the true board state.

Importantly, these observations are player-relative. Two different hidden board states may produce identical observations for a given player. From the agent's perspective, such states are indistinguishable.

As a result, the agent cannot condition its actions on the true board state. Any decision must be made based solely on the information available through observations.

\subsection{Belief over Hidden States}

Because the true board state is unobservable, the agent must reason over a set of possible hidden states that are consistent with the observations made so far. This set represents the agent's uncertainty about the game.

In this thesis, the term belief state refers to this set of plausible hidden board states, together with an implicit weighting induced by the agent's sampling and search process. The belief is not represented as an explicit probability distribution over all states. Instead, it is approximated by sampling and reasoning over multiple candidate states during search.

This approach avoids committing to a single guessed reality and instead allows the agent to evaluate actions across different possible hidden states.


\subsection{Action Selection under Uncertainty}

At any decision point, the agent must select a single action, even though multiple hidden states are possible. An action that is optimal in one hidden state may be suboptimal or even illegal in another.

This creates the central challenge of imperfect information games: the agent must choose actions based on incomplete and ambiguous information, without access to the true state of the game.

The methods studied in this thesis differ primarily in how they handle this uncertainty:

\begin{itemize}
  \item Determinization-based methods select a single sampled hidden state and plan as if it were correct.
  \item Belief-state methods evaluate actions across multiple sampled states.
  \item Learning-based methods attempt to approximate good decisions under uncertainty through self-play and function approximation.
\end{itemize}


\subsection{Objective and Value Definition}

The objective of the agent is to maximize the probability of winning the game. Following standard practice in self-play reinforcement learning, the value of a game state is defined from the perspective of the player to move.
Concretely:
\begin{itemize}
  \item A positive value indicates that the current player is expected to win.
  \item A negative value indicates that the current player is expected to lose.
\end{itemize}

This definition is independent of player color. When the agent plays as black, it aims to maximize black's chance of winning; when it plays as white, it aims to maximize white's chance of winning. During search and training, value estimates are adjusted appropriately when the player to move changes.

\subsection{Evaluation Metrics}

The primary performance metric used in this thesis is win rate against fixed baselines under controlled experimental conditions. Additional metrics, such as game length and training stability, are used to provide further insight into agent behavior.

The goal of the evaluation is not to establish optimal play, but to compare how different approaches handle uncertainty and how learning-based methods interact with belief-state search in practice.

\subsection{Summary}

Phantom Go presents an imperfect information setting where the agent must reason under persistent uncertainty about the true board state. The agent's observations are partial and ambiguous, multiple hidden states may be indistinguishable, and actions must be chosen without access to the true game state. The following sections describe how this uncertainty is handled: first through a particle-based belief representation, then through search-based and learning-based methods built on top of it.


\section{Particle-Based Belief Representation}
\label{sec:particle_sampler}

In this thesis, a particle-based belief representation is used to approximate the set of possible hidden board states in Phantom Go. The following section describes the specific sampler implementation used by the agents.

\subsection{Motivation}

In partially observable environments, an agent maintains a belief state, that is a probability distribution over possible underlying states consistent with the observation history.\cite{Veness2010pomdps}
In practice, such distributions are often approximated using particle-based representations, where the belief is represented by a finite set of sampled states. This approach originates from Sequential Monte Carlo methods, which approximate probability distributions using weighted samples that are periodically resampled to avoid degeneracy.\cite{Doucet2007particle}

In the context of Phantom Go, maintaining an explicit probability distribution over all possible board configurations is infeasible due to the combinatorial explosion of states.
Instead, a particle-based approach allows the agent to maintain a manageable set of plausible hidden states that are consistent with its observations. This representation can be updated efficiently as new observations are received.


\subsection{Particle Sampling and Update Procedure}

An agent's belief over the true hidden state is maintained by a particle sampler.
Rather than storing an explicit probability distribution over all possible board configurations, the sampler maintains a weighted set of particles, where each particle is a fully specified game state together with a scalar weight.

The sampler supports an optional opponent policy that can influence how opponent actions are sampled during belief updates.
For the BS-MCTS agent~\ref{sec:bs_mcts}, no opponent policy is provided and all opponent actions are sampled uniformly.
For the AlphaZero-inspired (AZBSMCTS) agent described in Section~\ref{sec:azbsmcts}, the neural network's policy head is used as the opponent policy, producing non-uniform particle weights that reflect the network's estimate of likely opponent behavior, assuming the opponent acts according to the learned policy. This difference in sampling strategy is a key distinction between the two agents and affects both the diversity and the weighting of particles.

After every real move in the game, the particle set is updated in a step that depends on who acted:

\begin{itemize}
  \item \textbf{Agent move:} Each existing particle is advanced by applying the agent's chosen action. A particle is retained only if its resulting observation tensor matches the observation the agent actually received. Surviving particles inherit their parent's weight. This ensures that the belief remains consistent with the agent's own actions and observations.
  \item \textbf{Opponent move:} For each existing particle, the sampler considers the opponent's legal actions. Actions are sampled according to the opponent policy if one is provided, or uniformly otherwise. Each sampled action is applied and the resulting child state is kept only if the agent's observation matches the one actually received. The child particle's weight is the product of the parent weight and the action's sampling probability. A configurable number of matching children are sought per parent particle.
\end{itemize}

After each update the particle weights are normalized to sum to one. A temperature parameter can be applied to the weights after opponent resampling to control the sharpness of the belief distribution. If the number of surviving distinct particles exceeds a configured maximum, only the highest-weight particles are retained.

For BS-MCTS, because opponent actions are sampled uniformly, all surviving particles receive equal weights during opponent resampling. The particle weights therefore reflect only consistency with observed information rather than any model of opponent behavior. In contrast, for AZBSMCTS, the opponent policy produces non-uniform sampling probabilities that lead to a more informed belief distribution, as particles consistent with likely opponent actions receive higher weights. This allows AZBSMCTS to focus its search on more plausible hidden states compared to BS-MCTS's uniform sampling approach.

\subsection{Particle Collapse and Rebuild}

Over time, particles may collapse onto a small subset of states, a phenomenon known as particle degeneracy, which is commonly mitigated by resampling the particle set to restore diversity.
Particle collapse refers to the situation where all particles are eliminated during an update step, leaving the sampler with an empty particle set. \cite{Arulampalam2002tutorial}
This can occur if no sampled hidden state produces an observation consistent with what the agent actually saw. For example, if the agent receives an observation that is impossible under any of the existing particles, then all particles will be discarded.

To recover from collapse, the sampler implements a particle rebuild procedure. The full observation history, consisting of who acted, the agent's taken actions and the agent's received observations at each step, is stored alongside the particle set. At regular intervals, checkpoints are saved that record a snapshot of the particle set at that history step.

When a rebuild is triggered, the sampler replays the stored observation history from the most recent valid checkpoint (or from the initial game state if no checkpoint is available). To improve the chances of success, each rebuild attempt uses progressively scaled-up parameters: higher maximum number of distinct particles, more matches per parent particle and higher temperature. A configurable number of rebuild attempts are made, starting from different checkpoints, before the sampler falls back to its last successfully sampled particle.

\subsection{Sampling for Search}

At each decision point, the search procedure requests a particle from the sampler. The sampler draws from its weighted particle set using the normalized weights as a categorical distribution and returns both the serialized game state and its associated weight. The weight serves as the prior probability of the determinization and is used by the search tree to weight that sample's contribution during action selection.

\subsection{Key parameters}
The particle sampler is governed by the following parameters:
\begin{table}[H]
  \centering
  \begin{tabular}{@{} l l @{}}
    \toprule
    Parameter            & Description                                              \\
    \midrule
    Number of particles  & Maximum number of distinct particles to maintain         \\
    Matches per particle & Number of matching children sought per parent particle   \\
    Rebuild attempts     & Number of rebuild attempts before fallback               \\
    Checkpoint interval  & Steps between saved checkpoints for rebuild              \\
    Temperature          & Temperature applied to weights after opponent resampling \\
    \bottomrule
  \end{tabular}
\end{table}

\subsection{Summary}

The particle sampler maintains a weighted set of observation-consistent hidden states that approximates the agent's belief. Particles are updated after each move through observation-consistent filtering and, for AZBSMCTS, weighted by a learned opponent policy. A checkpoint-based rebuild mechanism recovers from particle collapse. This representation is shared by both agents studied in this thesis and provides the belief foundation on which their respective search procedures operate.

\section{BS-MCTS for Phantom Go}
\label{sec:bs_mcts}

The Belief-State Monte Carlo Tree Search (BS-MCTS) agent used in this thesis follows the algorithm proposed by Wang et al.\cite{Wang2015bsmcts}. This section provides a brief overview of the method and notes the specific choices made for the Phantom Go implementation.

\subsection{Motivation and Overview}

In Phantom Go, the true board state is hidden from the player and decisions must be made based on partial observations. Determinization-based approaches address this uncertainty by sampling a single hidden state and planning as if it were correct. As discussed in Section~\ref{sec:determinization}, this can lead to inconsistent decision making due to strategy fusion and non-locality.\cite{Cowling2012ismcts}
Belief-State Monte Carlo Tree Search addresses this issue by reasoning over multiple possible hidden states simultaneously rather than committing to a single guess.

The search tree is a \emph{belief tree} in which nodes are indexed by observation strings rather than full game states, so that a single node may correspond to several distinct hidden states (called \emph{determinizations}).
Per-determinization statistics (visit counts, running-average rewards and sampler-provided prior weights) are maintained separately within each node, allowing the agent to track value estimates for each sampled hidden state while sharing the tree topology across determinizations that produce the same observation.\cite[Sec.~3]{Wang2015bsmcts}

The agent performs $T$ outer iterations per move. In each iteration, a determinization is sampled from the particle set (Section~\ref{sec:particle_sampler}) together with its prior weight. For that determinization, $S$ simulations of MCTS are run, each consisting of selection, expansion, random rollout and backpropagation. Terminal returns are discounted by $\delta^{l}$, where $l$ is the game length and $\delta$ is a discount parameter encouraging shorter games (see Section~\ref{sec:openspiel_mods}).

During selection at the agent player's nodes, the agent uses a UCT variant that incorporates belief-weighted action utilities, aggregating value estimates across determinizations.\cite[Eq.~(1)]{Wang2015bsmcts} At opponent nodes, actions are sampled proportionally to softmax-transformed belief-weighted utilities. After all simulations, the root action with the highest belief-weighted utility is selected.\cite[Alg.~1]{Wang2015bsmcts}

\subsection{Simplifications Relative to the Original BS-MCTS}

The original BS-MCTS framework proposed by Wang et al.\ includes additional mechanisms such as \emph{opponent guessing} and \emph{opponent predicting}, which aim to maintain and update beliefs over opponent behavior and future actions \cite{Wang2015bsmcts}.

The implementation used in this thesis adopts a simplified variant of BS-MCTS with the following simplifications and adaptations for Phantom Go:

\begin{itemize}
  \item \textbf{Particle-based belief:} Rather than assuming an external belief representation, the agent uses the particle sampler described in Section~\ref{sec:particle_sampler} with uniform opponent action sampling (no opponent policy). Particle weights therefore reflect only observation-consistency filtering.
  \item \textbf{Game-length discount:} A discount factor $\delta^l$, $l$ being the game length, is applied to terminal returns to discourage games from reaching the enforced maximum length (Section~\ref{sec:openspiel_mods}).
  \item \textbf{Default parameters:} The belief-weighting factors $\lambda_\text{guess}$ and $\lambda_\text{predict}$ are set to their default values of $1.0$. No additional tuning of these parameters was performed.
\end{itemize}

These simplifications reduce computational complexity and implementation overhead.

\subsection{Summary}

BS-MCTS provides a principled non-learning baseline that handles imperfect information through belief-state reasoning and multi-determinization search. It uses uniform particle sampling, UCT-based selection and random rollouts for leaf evaluation. By comparing against this baseline, the next section can isolate the contribution of neural-network-guided search and learned evaluation in the proposed AlphaZero-inspired agent.

\section{An AlphaZero-Inspired Method for Phantom Go}
\label{sec:azbsmcts}

This section describes the learning-based agent proposed in this thesis, referred to as AlphaZero-guided Belief-State MCTS (AZBSMCTS). The method builds directly on the BS-MCTS framework described in Section~\ref{sec:bs_mcts}, replacing random rollouts with neural network evaluations and using learned priors to guide action selection. The same belief tree structure is reused, and the same particle sampler is employed but with the neural network's policy head serving as an opponent policy, resulting in non-uniform particle weights.

\subsection{Why Vanilla AlphaZero Fails in Phantom Go}

AlphaZero was originally designed for perfect-information games, where the full game state is available to the agent at all times.\cite{Silver2017alphazero} In such settings, the policy and value networks can be trained directly on true board states and MCTS can evaluate actions under the assumption that the state is fully known.

In Phantom Go, these assumptions do not hold. The true board state is hidden and the agent only has access to partial observations. Providing a neural network with the full hidden state would leak information unavailable to the player, while training on raw observations alone leads to ambiguity, as multiple hidden states can correspond to the same observation.

As a result, naively applying AlphaZero to Phantom Go leads to inconsistent or misleading evaluations. Policy predictions may depend on hidden information the agent does not possess and value estimates may collapse due to uncertainty about the true state. These issues motivate the integration of belief-state reasoning into the AlphaZero framework.

\subsection{Architecture Overview}

AZBSMCTS combines belief-state search with a neural network in a way that preserves the core AlphaZero loop: the network guides MCTS, and MCTS produces improved policy targets for further training. The key adaptations are:

\begin{itemize}
  \item The search operates on a belief tree indexed by observations, identical to the tree used in BS-MCTS, rather than on fully observed game states.
  \item The neural network receives the \emph{observation tensor} of the \emph{current player to move} at any given node. This means that during the search traversal, the input perspective changes depending on whose turn it is. For the agent player's nodes the input reflects the agent's partial observation; for the opponent's nodes it reflects the opponent's partial observation as seen by the sampled determinization.
  \item Random rollouts are replaced entirely by neural network value estimates at leaf nodes.
  \item The UCT selection rule is replaced by PUCT, which uses neural network priors to bias exploration.
  \item The particle sampler uses the neural network's policy head as an opponent policy, so that opponent actions during belief updates are sampled according to learned action probabilities rather than uniformly. This produces non-uniform particle weights that reflect the network's estimate of likely opponent behavior, improving the quality of the belief distribution compared to the uniform sampling used in BS-MCTS.
\end{itemize}

\subsection{Neural Network}

The agent uses a small feed-forward network with two hidden layers (256 units each, ReLU activations) and two output heads:

\begin{itemize}
  \item A \textbf{policy head} that outputs logits over all actions. These are masked to legal actions at the current determinization and converted to probabilities via softmax. In the context of imperfect information, the policy head learns action preferences that are robust across multiple possible hidden states consistent with the current observation.
  \item A \textbf{value head} that outputs a scalar in $[-1, 1]$ (via $\tanh$), estimating the expected game outcome from the current player's perspective. Because the network sees only observations rather than full states, this estimate implicitly reflects an average over the hidden states consistent with the current observation.
\end{itemize}

The input to the network is the observation tensor of the \emph{side to move}, not the agent player specifically. This ensures that during search traversal, opponent nodes are also evaluated from the opponent's observational perspective under the sampled determinization.

\subsection{Differences from BS-MCTS in Search}

AZBSMCTS shares the same outer loop as BS-MCTS: $T$ determinizations are sampled from the particle set and for each determinization $S$ simulations are performed. The key differences lie in the inner search procedure:

\subsubsection{Expansion with Neural Network Priors}

When a node is first visited, the neural network's policy head is evaluated on the corresponding game state. The resulting masked softmax probabilities are stored as per-action priors $p_{\gamma,a}$ within the determinization's action statistics. These priors guide exploration during subsequent visits via the PUCT formula.

\subsubsection{PUCT Selection}

For the agent player's turn, AZBSMCTS replaces the UCT rule with PUCT:
\[
  a^* = \arg\max_a \left[ Q(a) \;+\; c_\text{puct} \cdot P(a) \cdot \frac{\sqrt{N_B + 1}}{1 + N_{B,a}} \right]
\]
where $Q(a) = \sum_\gamma w_{\gamma,a} \big/ \sum_\gamma n_{\gamma,a}$ is the mean value aggregated across all determinizations, and $P(a)$ is the weighted average neural network prior across determinizations, weighted by each determinization's visit count. $N_B$ and $N_{B,a}$ are the total and per-action visit counts aggregated across all determinizations at the node.

For the opponent's turn, the same softmax-based opponent prediction as in BS-MCTS is used, sampling actions proportional to $\text{softmax}(\lambda_\text{predict} \cdot U_B(a))$.

\subsubsection{Value Backpropagation}

Unlike BS-MCTS, which uses an incremental running-average update $u \leftarrow u + (r - u) / n$, AZBSMCTS accumulates a cumulative sum $w_{\gamma,a} \leftarrow w_{\gamma,a} + v$ and computes the action value as $Q = w / n$. The value $v$ used for backpropagation is the neural network's value estimate at the leaf, converted to the root player's perspective by negating it when the leaf's side to move differs from the root player.

Terminal states still use the game's actual return (discounted by $\delta^l$ as in BS-MCTS) rather than the neural network.

\subsubsection{Batched Leaf Evaluation}

To improve computational efficiency, leaf evaluations are deferred and batched. During each set of $S$ simulations for a given determinization, leaf nodes encountered during tree traversal are not immediately evaluated. Instead, the leaf state, its path from the root and the associated determinization key are recorded. After all $S$ simulations, a single batched forward pass through the neural network evaluates all pending leaves simultaneously, and their values are backpropagated along the stored paths.

\subsection{Root Action Selection and Policy Extraction}

After all $T \times S$ simulations, a policy vector is extracted from the root visit counts:
\[
  \pi(a) \propto N_{B,a}^{1/\tau}
\]
where $\tau$ is a temperature parameter. During self-play training, $\tau = 1$ is used for the first 20 moves to encourage exploration and $\tau \to 0$ thereafter. During evaluation, $\tau \to 0$ is always used. The final action is sampled from this distribution.

\subsection{Dirichlet Exploration Noise}

During self-play, Dirichlet noise is added to the root priors before search begins:
\[
  p'(a) = (1 - \varepsilon) \cdot p(a) + \varepsilon \cdot \eta_a, \quad \eta \sim \text{Dir}(\alpha)
\]
where $\varepsilon$ is the noise weight and $\alpha$ is the Dirichlet concentration parameter. This is applied only during training and not during evaluation.

\subsection{Training Targets and Self-Play}

Training data is generated through self-play. In each self-play game, the agent repeatedly performs belief-state MCTS guided by the current neural network. For each visited position, the following targets are recorded:
\begin{itemize}
  \item A \textbf{policy target} $\boldsymbol{\pi}$, derived from the normalized visit counts of actions at the root of the search tree.
  \item A \textbf{value target} $z$, given by the final game outcome from the perspective of the player to move at that position, discounted by $\delta^l$.
\end{itemize}

The neural network is trained to minimize a combined loss:
\[
  \mathcal{L} = (z - v)^2 - \boldsymbol{\pi}^\top \log \mathbf{p} + c \|\theta\|^2
\]
consisting of mean squared error for the value head, cross-entropy for the policy head and $L_2$ regularization. This training procedure follows the core AlphaZero principle: the network learns from the outcomes of search rather than from raw experience alone.

\subsection{Summary}

\begin{table}[H]
  \centering
  \caption{Comparison of BS-MCTS and AZBSMCTS.}
  \label{tab:bsmcts_vs_azbsmcts}
  \begin{tabularx}{\textwidth}{@{} l X X @{}}
    \toprule
                           & \textbf{BS-MCTS}                              & \textbf{AZBSMCTS}                         \\
    \midrule
    Belief representation  & Uniform particle resampling                   & NN-guided opponent policy in sampler      \\
    Tree indexing          & Observation string                            & Same                                      \\
    Expansion              & Legal actions only                            & Legal actions + NN priors                 \\
    Agent player selection & UCT with belief-weighted $U_B$                & PUCT with aggregated $Q$ and $P$          \\
    Opponent selection     & Softmax on $\lambda_\text{predict} \cdot U_B$ & Same                                      \\
    Leaf evaluation        & Random rollout                                & NN value head                             \\
    Backpropagation        & Running average $u$                           & Cumulative sum $w$, $Q = w/n$             \\
    Root action            & $\arg\max_a\; U_B(a)$                         & Sample from $\pi(a) \propto N_a^{1/\tau}$ \\

  \end{tabularx}
\end{table}

AZBSMCTS retains the belief tree structure of BS-MCTS while enhancing the particle sampler with a neural-network-guided opponent policy and replacing rollout-based evaluation with learned policy and value functions. The neural network guides exploration via PUCT priors and provides leaf evaluations via its value head, and the improved visit-count policies produced by search are fed back as training targets through self-play. This makes it suitable for studying how AlphaZero-style learning interacts with belief-state reasoning in imperfect information games.

\section{Experimental Evaluation}

\subsection{Experimental Setup}

The experiments are conducted on Phantom Go using the OpenSpiel implementation.
After preliminary testing, a board size of $5 \times 5$ is chosen to balance computational feasibility with strategic complexity, as larger boards significantly increased the state space which led to constant particle collapse and exhaustive training times under the available resources.

In accordance to the requirements described in Section~\ref{sec:openspiel_mods},
a maximum game length of 125 moves is enforced to prevent infinite games and a discount factor $\delta^l$ with  $\delta = 0.999$ is applied to terminal values to encourage timely conclusions.

For standard Go, play on a $5 \times 5$ board is considered solved and the optimal komi, meaning the komi that makes optimal play end in a draw, is known to be 25.\cite{vanderWerf2003solved}
Meanwhile, choosing a komi for Phantom Go is non-trivial due to the hidden information and the fact that the true board state is never fully revealed.
Unideal komi values can lead to unbalanced games where playing as one color has a significant advantage over the other, which can skew training dynamics and evaluation results, making it difficult to assess agent performance fairly.

For the purposes of this thesis, however, a default komi value of 7.5 is used, which is the standard value in OpenSpiel's Phantom Go implementation and provides a reasonable balance between the first-move advantage and the uncertainty inherent in the game.
As experiments are focused on comparing different agents under identical conditions with balanced color assignments, the specific choice of komi is less critical than ensuring it is consistent across all evaluations.

Unless otherwise stated, all agents are given identical per-move computational budgets to ensure fair comparison.

\subsection{Agents}

The following agents are evaluated:

\begin{itemize}
  \item \textbf{Random Agent}: An agent that selects legal actions uniformly at random. This agent serves as a lower-bound baseline.
  \item \textbf{BS-MCTS}: The belief-state Monte Carlo Tree Search agent described in Section~\ref{sec:bs_mcts}. This agent does not use learning and relies entirely on belief-state sampling and search.
  \item \textbf{AlphaZero-Inspired Belief Agent}: The learning-based agent described in Section~\ref{sec:azbsmcts}, which combines belief-state MCTS with a neural network trained through self-play.
\end{itemize}

All agents use the same search parameters when applicable.

\subsection{Training Configuration}
The training configuration was chosen to prioritize experimental clarity, stability and fairness over maximum playing strength. Rather than performing extensive hyperparameter optimization, all parameters were fixed in advance and held constant across all experiments. This ensures that observed differences in performance can be attributed to the presence or absence of learned guidance rather than unequal tuning effort.

The AZBSMCTS agent was trained through self-play for 1000 games. After each self-play game, the neural network was updated for 5 epochs on mini-batches of size 64 using a learning rate of $1 \times 10^{-4}$. A replay buffer with a maximum capacity of 50000 examples was used to bound memory usage and prevent late-stage training from becoming dominated by early, potentially low-quality data.

The search budget of $T = 8$ iterations with $S = 4$ simulations per sample was chosen to provide a minimal but non-trivial search that remains feasible on consumer hardware while still allowing agents to distinguish the value of different actions. The belief sampler maintains 50 distinct particles with up to 15 forward-simulation matches per particle and 5 rebuild attempts, providing reasonable coverage of the belief space without excessive computation.
These parameters were fixed throughout training.
During evaluation, exploration noise was disabled and actions were selected deterministically.

Only minimal exploratory runs were conducted to verify that the chosen configuration did not lead to pathological behavior such as divergence, degenerate policies or unstable training. Beyond this sanity checking, no hyperparameter optimization was performed. The reported configuration should therefore be interpreted as a set of controlled defaults rather than optimized settings.

\subsection{Evaluation Protocol}

Evaluation was performed by playing a fixed number of games under identical conditions between the AZBSMCTS agent at multiple stages of training against two baseline opponents: BS-MCTS and the Random agent. Five checkpoints were selected at 100, 300, 500, 700 and 1000 self-play training games, representing evenly spaced snapshots of the learning process from early to final training.

For each checkpoint, the AZBSMCTS agent played 50 games as black and 50 games as white against each opponent, yielding 100 games per matchup with balanced color assignments. All agents received identical search and sampler parameters during evaluation, as listed in Table~\ref{tab:hyperparams}, ensuring that differences in performance reflect only the quality of the learned policy and value functions.

The primary evaluation metrics are win rate, reported per matchup and as a function of training progress, and game length. Win rates measure whether the learning-based agent improves over training relative to the baselines. Game lengths provide additional insight into how agent behavior evolves, for instance whether the agent learns to play more efficiently or becomes overly passive.
